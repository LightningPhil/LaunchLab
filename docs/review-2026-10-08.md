## Licence assessment

A proprietary licence with a limited permission to use the hosted application fits the stated intent. Copyright already arises automatically in qualifying original software in the UK; the licence defines what others may do with it. It does not transfer ownership. [UK Intellectual Property Office overview](https://www.gov.uk/copyright/overview)

The revised draft retains the existing hosted-only permission and England-and-Wales jurisdiction. Public offline use, redistribution and self-hosting require separate written permission. The build scripts remain available to the owner and authorised developers. These assumptions should be confirmed before release, particularly if the owner is based in Scotland or Northern Ireland or wants to offer an official offline download.

The original terms prohibited all inspection and reverse engineering, claimed every intellectual-property right as the owner's, excluded virtually all liability, and allowed arbitrary termination. More restrictive language is not necessarily more effective. The revision:

- Limits the ownership claim to rights actually owned or licensed and preserves third-party permissions.
- Allows normal browser copies needed to use the service.
- Preserves applicable statutory exceptions. UK law prevents contracting out of certain necessary backups, interoperability decompilation and lawful observation, study and testing. [CDPA section 296A](https://www.legislation.gov.uk/ukpga/1988/48/section/296A/data.html)
- Adds explicit consumer and non-excludable liability protections, including negligence causing death or personal injury. Unfair consumer terms can be unenforceable. [Consumer Rights Act section 62](https://www.legislation.gov.uk/ukpga/2015/15/section/62/data.html), [section 65](https://www.legislation.gov.uk/ukpga/2015/15/section/65/data.html)
- Uses more measured withdrawal and breach provisions, and preserves mandatory consumer protections in the jurisdiction clause.

The significant limitation is the earlier MIT release. Changing the current licence or making the old repository private does not simply recall permissions already granted to recipients of those copies. MIT permits copying, modification and redistribution subject to its notice requirements; the revised licence explicitly preserves valid earlier grants. People may continue using an earlier authorised MIT version. New original additions can be licensed differently where the necessary rights are owned. [MIT terms](https://opensource.org/license/mit), [GitHub's guidance on changing licences](https://opensource.guide/legal/#what-if-i-want-to-change-the-license-of-my-project)

Keep the source repository private if the aim is to avoid granting GitHub users permission to fork it: public repositories carry platform-level viewing and forking permissions. A publicly served JavaScript application also necessarily delivers executable code and assets to visitors. A licence can restrict reuse; it cannot technically prevent someone saving delivered files. [GitHub Terms, section D.5](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#5-license-grant-to-other-users)

Ownership remains a factual check. The source snapshot cannot establish whether previous contributors, employment terms, copied snippets or commissioned assets carry additional rights. MIT dependencies can coexist with a proprietary application when their notices and permissions are preserved. Artwork records describe generated illustrations; retain the source/provenance records and do not assume that a blanket copyright statement proves every asset is exclusively protectable. [IPO ownership guidance](https://www.gov.uk/guidance/ownership-of-copyright-works)

Before public release, have a UK software/IP solicitor review this draft against the actual ownership history, intended users and distribution model, including how the terms will be brought to users' attention. The current manual displays them but does not implement an explicit acceptance flow. Preserve the old repository history privately and record the exact last MIT release and first proprietary release.

## Remaining technical findings

The residual audit chain is `vite-plugin-singlefile → micromatch → braces`. The advisory concerns deeply nested brace patterns exhausting the build process's stack; no patched braces version was listed on the review date. This is development tooling, not a shipped browser dependency. In the installed plugin, matching is gated on a non-empty `inlinePattern`; this project does not supply one, so the affected matching path is not used by its current configuration. This is a code-based reachability assessment, not a claim that the dependency itself is fixed. Do not force npm's suggested downgrade to plugin 0.9.0 without separate compatibility work. [Advisory GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)

The main JavaScript bundle is approximately 546 kB before compression and the separately loaded Orrery bundle is approximately 584 kB. Vite warns about chunks over 500 kB. The portable file is approximately 11.0 MB, largely because all artwork and code are embedded. These are performance considerations, not build failures; use the normal multi-file build for the hosted website.

TypeScript's strict mode is disabled in the existing configuration. Typechecking passes under that configuration. The project has substantial model and geometry tests, but some presentation tests assert source structure, so the passing suite should not be interpreted as full UI coverage.

No backend, authentication system or server secrets are needed for the inspected client application. A limited search found no common GitHub/AWS private credential patterns or private-key headers outside generated and dependency files; this is not a complete secret scan. Nothing about future hosting access or privacy settings has been verified remotely.

## Follow-up: Orrery touch panning

Added two-finger panning alongside the existing one-finger rotation and pinch zoom. The midpoint's movement is accumulated once per rendered frame and uses the same screen-space camera translation as right-mouse dragging. Panning releases a followed planet, and multi-touch releases cannot trigger canvas planet selection. Contact cancellation, capture loss, window blur and closing the Orrery clear the relevant gesture state. A touch hint appears on narrow screens and devices with a coarse pointer.

The browser check also exposed an existing crash after closing a planet's details: the hidden distance field still tried to read a now-unselected planet. The distance refresh now handles an empty selection. Repeating Earth selection → close-up → close details → resume confirms that simulation time continues advancing, with no errors from the rebuilt Orrery.

Validation: all **184 tests pass**, including seven new navigation tests covering phone/tablet/desktop proportions, zoom limits, rolled/top views, simultaneous pan and pinch, contact transitions and interruption. Integration tests exercise the installed Three.js TrackballControls using pointer events in a Node DOM harness. `npm run build` passes TypeScript and regenerates both the hosted and portable builds. Browser checks at 390×844 and 768×1024 verify layout, the phone hint, planet selection, close-up and reset. Physical multi-touch input was not available to the browser automation, so on-device gesture feel still needs a phone/tablet check. Nothing was pushed or deployed.
